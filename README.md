# MultyHome — учебный Telegram-бот для Яндекс Дома

Тема диплома: «Управление умным домом через Telegram-бота».
Это учебный проект на Python. Каждый пользователь подключает
свой Яндекс Дом. Сервер бота получает команды из Telegram и обращается к API
Яндекса с токеном именно этого пользователя.

Сейчас доступны список устройств, просмотр состояния, включение/выключение,
яркость, цвет RGB/HSV, температура белого света, заданная температура устройства,
громкость, числовые настройки, режимы и сцены освещения. Бот читает `capabilities`
из ответа Яндекса и разрешает только заявленные устройством настройки.
Это не поддержка всех возможных функций Яндекс Дома: относительные изменения,
переключатели типа `toggle`, видеопотоки и домашние сценарии пока не реализованы.
Датчики можно просматривать; показание температуры датчика не является командой
установки температуры.

Для Станций добавлена отдельная неофициальная интеграция эквалайзера:
[пошаговое подключение на Mac](STATION_SETUP.md). Настоящая Станция пока не
проверена; сначала подключите сессию локально. `/status` также читает известные
поля настроек Станции из обычного ответа Яндекса.

## 1. Сначала проверить без токенов

Нужен Python 3.10 или новее. На Linux/macOS из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bot.py --demo-console
```

На Windows:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe bot.py --demo-console
```

Введите по очереди `/devices`, `/on 1`, `/status 1`, `/off 1`, `/status 1`, `exit`.
Состояние учебной лампы должно измениться. Это проверка логики программы;
настоящие устройства и Telegram в ней не участвуют.

`.venv` — отдельная папка с Python-библиотеками именно этого проекта.
`pip install` устанавливает две библиотеки: `requests` для HTTP-запросов
и `python-dotenv` для чтения настроек из `.env`.

## 2. Запустить учебные устройства через Telegram

Скопируйте `.env.example` в `.env` (можно через файловый менеджер).
Не перезаписывайте существующий `.env`: в нём могут быть ваши настройки.
В `.env` впишите токен своего бота от BotFather в `TELEGRAM_BOT_TOKEN`.
Оставьте `DEMO_MODE=1`. Запустите:

```bash
.venv/bin/python bot.py
```

На Windows используйте `.venv\Scripts\python.exe bot.py`.
В личном чате с ботом отправьте `/start`, затем те же команды из первого шага.
У каждого пользователя свой набор виртуальных устройств.

Бот использует long polling: сам спрашивает Telegram о новых сообщениях.
Для этого не нужен публичный сайт или HTTPS-сервер. Бот работает, пока работает
программа и есть Интернет. `Ctrl+C` останавливает её.
Запускайте только один экземпляр с одним Telegram-токеном.
При запуске программа отключает webhook этого бота и удаляет накопленные
сообщения, чтобы после перезапуска не выполнить старые команды управления.

## 3. Подключить настоящие дома

Сначала перевыпустите Client secret, который был отправлен в переписке.
Новый секрет не публикуйте и не отправляйте в чат.

В настройках приложения Яндекс OAuth:

- включите права чтения и управления домом: `iot:view`, `iot:control`;
- укажите Redirect URI: `https://oauth.yandex.ru/verification_code`;
- проверьте, что приложение позволяет авторизацию будущих пользователей,
  а не только аккаунта разработчика; доступность определяется настройками Яндекса.

В `.env` укажите `YANDEX_CLIENT_ID`, новый `YANDEX_CLIENT_SECRET` и `DEMO_MODE=0`.
Перезапустите бота. Каждый пользователь выполняет в личном чате:

1. `/connect` — бот выдаёт ссылку на авторизацию Яндекса.
2. Пользователь открывает ссылку, входит в **свой** аккаунт и разрешает доступ.
3. Яндекс показывает одноразовый код. Пользователь отправляет `/code КОД`.
4. Бот обменивает код на токен и сохраняет связь с Telegram ID пользователя.
5. `/devices` показывает устройства его дома.

`/code` принимает короткоживущий код авторизации, а не Client secret и не токен.
Бот пытается удалить сообщение с кодом. Получить код и отправить его нужно
в течение пяти минут после `/connect`. Если код или токен перестал работать,
повторите подключение. Автоматическое обновление токенов пока не реализовано.
Ручной ввод кода подходит для учебного прототипа; публичный сервис лучше перевести
на веб-обработчик OAuth с проверкой `state`.

Токены сохраняются в `users.json` рядом с программой, секрет приложения — в `.env`.
Оба файла исключены из Git. На Linux `users.json` создаётся с правами только
для владельца процесса. Токены в нём не зашифрованы: для дипломного прототипа
используйте доверенную машину, ограничьте доступ к файлам и не распространяйте их.
`/disconnect` удаляет подключение из бота. Отозвать выданные приложению права
можно в настройках Яндекс ID.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Подсказка |
| `/id` | Telegram ID отправителя |
| `/connect` | Подключить свой дом |
| `/disconnect` | Удалить подключение |
| `/devices` | Получить список устройств и их номера |
| `/status 1` | Прочитать состояние устройства №1 |
| `/on 1`, `/off 1` | Включить или выключить устройство №1 |
| `/capabilities 1` | Доступные настройки, диапазоны и названия режимов |
| `/capability_info 1` | Структура возможностей без ID, токенов и персональных значений |
| `/brightness 1 50` | Установить яркость |
| `/color 1 FF0000` | Красный цвет; HEX можно вводить с `#` или без него |
| `/white 1 4000` | Температура белого света в кельвинах |
| `/temperature 3 22.5` | Заданная температура в единицах устройства |
| `/mode 3 thermostat cool` | Выбрать режим из списка возможностей |
| `/volume 4 30` | Громкость в единицах устройства |
| `/range 1 ИМЯ ЗНАЧЕНИЕ` | Другая числовая настройка: например, `humidity` или `open` |
| `/scene 1 reading` | Сцена освещения из списка возможностей |
| `/station 2` | Состояние эквалайзера через отдельный API Станции |
| `/equalizer 2 on`, `/equalizer 2 off` | Включение/выключение эквалайзера после подключения |
| `/eqbands 2 -3 0 0 0 3` | Пять усилений эквалайзера, целые от -6 до 6 дБ |
| `/station_info 2` | Структура конфигурации Станции без секретных значений |

Числа и режимы в таблице — примеры для учебных устройств. Для настоящего дома
сначала выполните `/devices`, затем `/capabilities НОМЕР`. Используйте номер,
диапазон и названия режимов из ответа своего устройства. `/temperature` — заданная
температура устройства, а `/white` — цветовая температура света; это разные настройки.
`/scene` относится к сценам освещения лампы, а не к домашним сценариям Яндекса.
Для HSV цвет из HEX пересчитывается в тон, насыщенность и яркость; яркость цвета
входит в передаваемое значение HSV. Команда не включает лампу автоматически.

Проверки значений используют `parameters.instance`, `range.min`, `range.max`,
`range.precision` и список `modes` из возможностей устройства. Если числовые границы
не объявлены, бот не придумывает их: применяет только ограничения протокола
для `brightness`, `humidity` и `open` (0–100). Яндекс может дополнительно отклонить
команду. При `random_access=false` установка абсолютного значения отклоняется.
Режимы и сцены вводятся точно как в списке, включая регистр букв.

### Особые возможности Яндекс Станции

Станция может возвращать `equalizer`, `audio_player`, `speaker_do_not_disturb`,
`voice_enrollment` и другие типы, которых нет в публичном описании протокола
умений. Их наличие в ответе не доказывает, что они принимают команды через
наш endpoint `https://api.iot.yandex.net/v1.0/devices/actions`.
По названию нельзя узнать правильные `instance`, `value` и способ авторизации.
Для эквалайзера теперь есть отдельный адаптер API конфигурации и локальное
подключение сессии: см. `STATION_SETUP.md`. Изменение других внутренних настроек
не реализовано; взаимодействие с настоящей Станцией ещё требует проверки.

Чтобы исследовать ответ вашего устройства:

1. Обновите проект и перезапустите бота.
2. В Telegram отправьте `/devices`.
3. Отправьте `/capability_info НОМЕР_КОЛОНКИ`.
4. Передайте полученный ответ разработчику проекта.

Эта команда только читает данные устройства. Она показывает типы возможностей
и структуру `parameters` и `state`. Все значения заменяются на обозначения
`<string>`, `<number>` и `<boolean>`; имя устройства, ID и весь аккаунт не выводятся.
`null` означает отсутствие данных, а не выключенное состояние настройки.
Структура помогает понять поля ответа, но сама по себе не подтверждает формат
команды управления. Для реализации нужны описание метода или подтверждённые
форматы запросов и проверка с вашим аккаунтом.

Например, открытая интеграция YandexStation настраивает эквалайзер через
отдельный метод конфигурации в `iot.quasar.yandex.ru`. Это другой API;
его нельзя просто подставить вместо текущего адреса, считая авторизацию одинаковой.
Не отправляйте пароли, токены или cookie в чат для такой проверки.

Источники проверки:
[публичные типы умений](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/capability-types),
[метод управления](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-capabilities),
[реализация настройки эквалайзера в YandexStation](https://github.com/AlexxIT/YandexStation/blob/master/custom_components/yandex_station/select.py).

После обновления на Mac остановите бота через `Ctrl+C`, затем в каталоге проекта:

```bash
git pull --ff-only
.venv/bin/python bot.py
```

Если Git сообщает о ваших изменённых файлах, сохраните их перед обновлением;
не удаляйте изменения вслепую. Зависимости для новых команд остались прежними.

Для проверки новых настроек без Telegram:

```bash
.venv/bin/python bot.py --demo-console
```

В этой консоли последовательно введите:

```text
/devices
/capabilities 1
/brightness 1 70
/color 1 FF0000
/white 1 4000
/scene 1 reading
/capabilities 3
/temperature 3 22.5
/mode 3 thermostat cool
/volume 4 30
/status 3
exit
```

Учебный дом содержит лампу №1, розетку №2, кондиционер №3, колонку №4 и Станцию
с эквалайзером №5.
Чтобы проверять эти устройства через Telegram, поставьте `DEMO_MODE=1` в `.env`
и перезапустите бота. Для настоящего дома верните `DEMO_MODE=0` и снова перезапустите.

Номера берутся из последнего `/devices` конкретного пользователя.
После перезапуска список нужно запросить заново. Групповые чаты игнорируются.
Команда «выполнена» означает подтверждение Яндекс API; фактическое состояние
проверьте через `/status` и на самом устройстве. Некоторые устройства обновляются
с задержкой.

## Файлы проекта

- `bot.py` — принимает сообщения, разбирает команды и отправляет ответы.
- `yandex_home.py` — запросы к Яндексу и учебные устройства.
- `accounts.py` — авторизация и отдельный токен каждого пользователя.
- `capabilities.py` — доступные команды и проверка их значений по данным Яндекса.
- `station_state.py` — чтение известных полей состояния Станции.
- `station_api.py` — отдельная сессия Станции и настройка эквалайзера.
- `station_login.py` — локальная привязка сессии к Telegram ID.
- `STATION_SETUP.md` — подробная инструкция подключения Станции на Mac.
- `.env.example` — образец настроек без секретов.
- `tests/test_bot.py` — проверки логики с подменёнными внешними API.
- `LESSON_01.md` — объяснение первого шага простыми словами.
- `LESSON_02.md` — как читать возможности устройства и управлять настройками.

Проверки:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Эти тесты проверяют команды, разделение пользователей и обработку ошибок.
Они не доказывают доступность настоящего Telegram или Яндекс Дома.
Для полной проверки нужны настоящие токены и испытание из личного чата.

## Работа в облачной среде

Проект расположен в `/workspace/MultyHome`. Зависимости устанавливаются в `.venv`.
Нужен HTTPS-доступ к `api.telegram.org`, `api.iot.yandex.net`, `oauth.yandex.ru`.
Черновик настроек сети сохраняется отдельно; его сохранение не открывает сеть
в текущей машине автоматически. Секреты размещайте в локальном игнорируемом `.env`
на доверенной машине. Не включайте `.env` и `users.json` в общедоступный снимок среды.
В учебном запуске в облаке используйте `--demo-console` без секретов.

## Если бот отвечает медленно

В `.env` добавьте `DIAGNOSTICS=1` и перезапустите бота. Отправьте одну команду
`/help`, затем `/devices` и посмотрите на время в терминале:

- `Telegram sendMessage` — сколько заняла отправка ответа;
- `Яндекс GET` или `Яндекс POST` — время запроса к Яндексу;
- `Обработка команды` — время подготовки ответа, включая запрос к Яндексу;
- `Telegram getUpdates` — ожидание нового сообщения. Значение около 25 секунд
  при отсутствии сообщений нормально: Telegram ждёт сообщения и должен
  вернуть его сразу при появлении. Это не задержка обработки каждой команды.

Диагностика не печатает токены, коды авторизации и содержимое сообщений.
Время измеряется на машине, где запущен бот. Без этих замеров нельзя установить
причину конкретной задержки. После проверки верните `DIAGNOSTICS=0`.

Если тормозит `/help`, причина не в Яндекс API этой команды: она к нему не
обращается. Но она может ждать предыдущую медленную команду: этот простой бот
обрабатывает сообщения по очереди. Если медленны только `/devices`, `/status`
или управление, посмотрите на время запроса к Яндексу.

Программа повторно использует HTTP-соединения с Telegram и Яндексом, чтобы не
создавать новое соединение для каждого запроса. При сетевых ошибках ожидание
может быть значительно дольше. Если видите сообщение о конфликте запуска,
проверьте, что бот не запущен одновременно на компьютере и в облаке.

Чтобы получить изменения из GitHub, остановите бота (`Ctrl+C`), выполните
`git pull --ff-only` в каталоге проекта и запустите его заново. Если скачивали ZIP,
скачайте свежую версию; сохраните свои `.env` и `users.json`, не публикуя их.

## Следующие этапы диплома

1. Проверить новые команды на вашем Telegram-боте и настоящем доме.
2. Добавить кнопки, чтобы пользователю не приходилось помнить номера и команды.
3. Добавлять оставшиеся функции по заявленным возможностям устройств.
4. Описать требования, схему работы, алгоритмы и реальные результаты испытаний.
   Проверку каждого нового этапа выполняем до перехода к следующему.

[Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/),
